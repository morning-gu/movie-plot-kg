# temporal 宽窗口(ID 序时间窗)设计 v2

日期:2026-10-23
状态:已批准(成功线 A:temporal ≥0.667 + 一轮预算内校准复跑)
前序:负结果档案 `eval/ANSWERING_OPTIMIZATION_REPORT.md`、QA 集全量校验

## 意图与为什么

temporal 意图 12 题长期 2/12(0.1667),是距 0.7 验收线(差 11.7pp)最大
的单点结构性缺口。

**失败机理(v1 侦察实证,审查确认)**:temporal 题问「X 之后发生了什么」。
问题**引用的事件 X**(餐厅讨论、墓地告别)语义上容易被向量检索命中;而
**答案(后续事件)与问题文本语义无关**,永远进不了 top-k。约 8/12 题的
检索 hit ≤0.33——不是模型笨,是用相似度去找「接下来会发生的事」注定失败。

本设计把 temporal 检索改写为:**用相似度找引用事件(锚点),沿片内时间
序向前开窗取后续事件**。

## 图谱事实(v2 修订,全部经 builder 审查 + 主会话双重复核)

**可用:**

1. **事件 ID 即全序**:`evt_{movie}_{场景号3位}_{序号2位}` 内嵌
   (movie, scene, ordinal),同一片内按 (scene, ordinal) 排序就是片内
   时间序——**无断口、不依赖任何边**。这是窗口机制的底座。
2. 22 个 temporal gold 事件全部是链上主事件(非子事件),ID 序即覆盖。

**不可用(v1 误判,v2 纠正):**

3. **PRECEDES 链有断口**:HK 在场景 010/013(零事件)处断成 3 段,Rock
   在 011/046 处同样断 3 段;只有 RD 完整。可变长路径走链会在断口死端。
   → 窗口不用链,用 ID 序。
4. **子事件不在链上**:Rock 场景 008 的 008_02–008_05(含 rk_f1 的 gold
   墙上勋章)PRECEDES 度数为 0,只有 008_01 在链上。锚点若落在此,
   链走窗口静默退化。→ ID 序窗口对子事件免疫。
5. **Location 不能作叙事段单位**:Rock 有两个空注记超级地点
   (365 + 301 事件,后者横跨 122 个场景——与 VirtualTime 同源的
   `d41d8cd9` 空串病,Location 维度同样中招,列入重建清单);墓地情节
   与书房闪回交替(电影真实结构),不折叠成一个段;RD 场景 002-003 的
   22 个事件(餐厅+车内+后续)共享同一地点注记。→ 地点只作**软停止
   信号**,不作窗口结构单位。
6. **Scene 节点跨片污染**(467 节点全标 tt0117500)、**VirtualTime 退化
   节点**:禁用(重建清单第 5、6 项)。

## 机制设计(v2)

### 触发(硬门,不变)

`plan.intent == "temporal"` 且仅此;planner 提示词零改动;非 temporal
48 题检索路径逐字节不变。

**新增前置**:实现前先做 **plan.intent 对齐测量**——60 题过一遍 planner,
记录 plan.intent vs 题面 intent 的混淆矩阵(planner 输出从未被下游用过,
无任何实测数据)。若非 temporal 题被误判为 temporal,窗口会在这些题上
生效——守门归因按「机制变更」处理并单独报告;误判率 >2 题则先回报再
继续(提示词不能动,只能靠文档说明与归因规则消化)。

### 锚点绑定(v2:多数票 + 锚点组末事件)

temporal plan 的向量召回中取 Event 标签命中:

1. 按 LOCATED_AT 分组**计票,空注记地点(d41d8cd9 类)不计票**;
   取票数最多的非空地点组(平票取最高分命中所在组;全部命中都是空
   地点时退化为 top-1 命中)
2. **锚点位置 = 该组内(场景号,序号)最大的事件**——「X 之后」语义上
   指 X 全部结束后;用组内末事件避免窗口从 X 中段开起
3. 无 Event 命中 → 不开窗(宁缺不污染)

### 窗口(v2:锚点相对 + ID 序,不走链)

从锚点事件起,按**本片 (场景号, 序号) 升序**取后续事件:

- **锚点残余**:锚点同场景内、序号大于锚点的事件(无条件全收——
  「紧接着」的答案最常在这里,v1 的段相对窗口正是漏掉这块)
- **后续**:跨场景继续按 ID 序收,直到触发停止:**第 2 个**非空且
  不同于锚点组的地点,或预算上限 **24 事件**,先到为准
- 子事件(链外)照收——ID 序不歧视;零事件场景号自动跳过
- 合计上限 24 + 锚点残余(回答端证据宽度敏感,预算是首要校准杠杆)

### 证据呈现与合并

- Evidence(source=`temporal_window`),text 前缀 `【时间序 {n}·场景{场景号}】`,
  n 在窗口内递增
- **同 node_id 时窗口行覆盖既有行**(向量/图证据里的同名事件换成带
  时间序标记的版本,保证时间线标记不被去重吃掉)
- planner 的 graph_queries 照常执行;窗口行追加在其后

### 全局模式

ID 序窗口天然按锚点事件的 movie_id 过滤——全局模式下锚点即使被别片
事件抢走,窗口也只在该片内开(不会注入别片时间线)。全局模式定位为
「功能正确」,评估只看 scoped。

## 评估协议

- **成功线(已确认,A)**:temporal ≥8/12(0.667);机制级:temporal
  mean hit_rate 0.15→≥0.5
- **守门**:非 temporal 48 题净变动 ≤±3 题;temporal 逐题归因
  (锚点绑对/窗口长度/作答吸收/判卷)
- 首跑若机制生效(hit_rate 达标)但题数 6-7:调预算(24→32)或停止
  信号(第 2→第 3 个地点)复跑**一次**;这是唯一预算内校准轮
- plan.intent 对齐测量先于一切实现

## 目标 / 非目标 / 反目标

**目标**:temporal ≥0.667(待确认);非 temporal 48 题零机制改动;
机制级可度量(hit_rate)。

**非目标**:全片时间线重组;rd_t3/hk_t3 弧线题;rd_t4/rk_t1 结构性
出局题;图谱修复(PRECEDES 断口、子事件挂链、空 Location 超级节点、
Scene 跨片污染、VirtualTime 退化——共 6 项重建清单)。

**反目标**:动 planner 提示词;任何影响非 temporal 检索路径的改动;
用 Scene 节点/Location 超级节点做窗口结构单位。
